## v1.1.0 — 2026-05-06 — capture + recall: closing the value loop

- **`templates/LAUNCH_FOOTER.md` portable convention sheet.** Single source of truth for capture + recall conventions — inbox-note format, source-priority rule, capture trigger, recall trigger, rules block. Lifted from the conductor's external `LAUNCH_FOOTER.md` so the conventions live inside the plugin and travel with installs.
- **CLAUDE.md injection on `kunskap learn enable` (P0 of the v1.1 value prop).** Adds a managed block bounded by `<!-- BEGIN/END kunskap (managed) -->` to the project's `CLAUDE.md` (creating the file if needed) carrying the LAUNCH_FOOTER body plus a Recall addendum: *"At the start of every new task, run `/kunskap:recall <keywords>` to surface prior learnings + research relevant to the goal."* Every session in a kunskap-enabled project sees the contract — no dependence on conductor-launched footers or description-triggered Skill auto-load. Idempotent: re-enable replaces the block in place. Tamper detection: the block carries a `<!-- kunskap:hash <sha256> -->` line; `learn disable` recomputes the hash and refuses if the body has been hand-edited inside the fence (no silent nuking of user edits). User content surrounding the block is preserved on both enable and disable.
- **`/kunskap:learn disable` round-trip cleanly removes the block.** When the managed-block hash matches, the block is excised (and the CLAUDE.md file removed entirely if the block was the only content). Manual-edit refusal exits 1 with an actionable stderr message; the marker stays put so the user can review and re-disable after manually cleaning up.
- **Per-write async sync via `PostToolUse(Write|Edit)` hook.** New `hooks/post-write-sync.sh` fires on every Write/Edit and (after path-prefix + traversal checks) commits + pushes inbox writes asynchronously. `async: true` in `hooks.json` per the canonical hooks reference; the script also self-backgrounds so the agent never blocks on git or network even if a Claude Code version doesn't honour `async`. Closes the SIGKILL/SIGHUP loss window left by the v1.0 SessionEnd hook (which silently dropped unpushed commits when the process died).
- **`SessionEnd` hook removed.** The per-write hook covers the use case more reliably (catches kill-9, SIGHUP, IDE-managed lifecycles where SessionEnd never fired). Net code-surface decrease.
- **`/kunskap:sync` slash command + `bin/kunskap sync` CLI.** Manual flush for the rare retry case (push failed earlier; user wants to deliberately flush before disconnecting). Loud about failures — exit 1 on push fail with clear stderr — opposite of the silent async hook, on purpose. Solo vaults exit 0 with a "not shared" message.
- **`kunskap learn status` surfaces uncommitted-inbox count.** New `INBOX:` line shows `0 uncommitted notes` when clean or `N uncommitted notes — run /kunskap:sync (or kunskap sync) to flush` when non-zero. Free visibility into pending captures.
- **`SessionStart` passive uncommitted nudge.** After the `git pull --rebase`, the hook prints a one-line warning to stderr if the inbox has uncommitted notes from a prior session: *"⚠ N uncommitted inbox note(s) from prior session — run /kunskap:sync to push."* No new hook firing in the hot path; one extra `git status` per session start.

## v1.0.1 — 2026-05-06 — curator + linter subprocess permission fix

- **`bin/kunskap curate` + `bin/kunskap lint` spawn shape.** Switched from `--permission-mode acceptEdits` to `--permission-mode dontAsk` paired with an explicit `--allowed-tools` allow-list at both spawn sites. Per canonical Claude Code permission docs (§Permission modes), `acceptEdits` auto-approves Edit/Write and a fixed set of filesystem commands (`mkdir`, `mv`, `cp`, etc.) but does NOT cover `Bash` git operations; in headless mode an unmatched git op falls through to a `canUseTool` callback that doesn't exist, so the agent aborts cleanly per its contract but never completes the work. `dontAsk` converts any unmatched tool into an explicit denial; the allow-list pre-approves exactly the tools each agent prompt invokes — no broader.
- **Curator allow-list (atomic per-article-commit MUST 1 unblocked).** `Read,Write,Edit,MultiEdit,Glob,Grep,Agent` + `Bash(git {status,diff,log,rev-parse,ls-files,check-ignore}:*)` (read-only) + `Bash(git {add,commit,mv,rm}:*)` (mutations) + `Bash({mkdir,jq,tee,date,grep,sort,uniq,kunskap}:*)` (run-record recipe + stub-discovery pipeline). Bare `git foo` form only — the cd-into-vault before spawn makes CWD = vault, so the agent's bare form is sufficient. `git push` is intentionally absent — the SessionEnd hook owns push (P2). `Bash(*)` is intentionally absent — that would be bypass-equivalent.
- **Linter allow-list (read-only invariant tightened).** Same shape as curator's but TIGHTER: no `Edit` / `MultiEdit` (the linter never modifies existing files); no `Bash(git {add,mv,rm}:*)` curator-style rules; instead a per-path exact match `Bash(git add _meta/last-run/linter.json)` for the run-record write — the SOLE permitted exception per linter MUST 8 + MUST 9. Plus `Bash({awk,find,xargs}:*)` for the canonical anchor-to-NR==1 frontmatter parsing recipe in `agents/linter.md` §Frontmatter parsing (MUST 3 staleness walk; the first smoke didn't catch this because the smoke vault had no stale drafts). The CLI authoritative invariant check (`status_before/after` + HEAD oid + `git log --name-only` enumeration, P4 §3) remains the trust boundary; the per-path allow rule is defense in depth.
- **Pass-2 empirical finding (`*` is a literal asterisk, not a glob).** During the dev dance, an end-to-end probe of `claude 2.1.129` revealed that `*` inside `--allowed-tools` matchers is a LITERAL character — `Bash(git -C * foo:*)` does NOT match `git -C /abs/path foo`. An earlier draft of this fix included redundant `Bash(git -C * <op>:*)` rules in both lists; binary-vs-docs check showed they were dead weight and they were dropped. Repros also confirmed `>` shell redirection defeats per-tool prefix matching (`Bash(echo:*)` does not match `echo foo > /tmp/x`) but `|` does not — so the linter directive prompt instructs the agent to use `jq -n ... | tee <path>` instead of `jq -n ... > <path>`. `--permission-mode dontAsk` is a canonical enum value alongside `acceptEdits`/`auto`/`bypassPermissions`/`default`/`plan` (visible in `claude --help`).
- **Real-usage finding 2026-05-06.** Surfaced by the first end-to-end smoke test against a fresh vault. Both agents aborted cleanly per their contracts (no half-state, vault byte-identical to pre-run — discipline held) but neither could complete the work. Ships the load-bearing `kunskap curate` flow that v1.0 packaged but couldn't actually run.
- **bats coverage extended.** New spawn-shape assertions in `tests/contract/role-cli.bats`: `--allowed-tools` + `--permission-mode dontAsk` present, `acceptEdits` regression caught, `bypassPermissions` and `Bash(*)` rejected (defense-in-depth against `/simplify` swapping to bypass for convenience), curator covers `add`/`commit`/`mv`/`rm` + `mkdir`/`jq`, curator omits `git push`, linter is provably tighter than curator (per-path `add`, no broad `git add:*`), linter covers MUST-3 frontmatter parsing (`awk`/`find`/`xargs`) and MUST-6 read-only git ops, both include `Agent` for subagent invocation, neither uses the dead `Bash(git -C * ...)` form (Pass-2 lock).
- `bin/kunskap version` bumps to `1.0.1`. Plugin manifest version bumps to `1.0.1`.

## v1.0.0 — 2026-05-05 — P6 search + polish + marketplace (v1.0 release)

- **`commands/recall.md` + `bin/kunskap recall <query> [--vault <abs-path>] [--author X] [--tag Y] [--limit N] [--format text|json]`.** Slash and CLI surface for searching the vault from inside a Claude Code session. Identity-independent — works on any machine regardless of role (P5 §8: read-only operations are orthogonal to identity gates). Vault resolves from `--vault` flag, then the project marker (`.claude/kunskap.json`), same shape as `lint` and `drafts`.
- **Two-stage search.** Stage 1 (load-bearing per design §Q8): `rg --json --type md --fixed-strings` over `<vault>/wiki/` + `<vault>/raw/inbox/`; jq normalizes paths to vault-relative form. Stage 2 (best-effort): `obsidian search query="..." format=json` reranks paths by Obsidian's relevance score. Detection chain: `command -v obsidian`, fallback to `/Applications/Obsidian.app/Contents/MacOS/obsidian-cli` on macOS, then `pgrep -x Obsidian`, then a `version`-call smoke (the binary exists even when the CLI toggle is off; the smoke catches that). When any check fails, Stage 1 carries silently.
- **Risk #2 (Obsidian CLI partially unverified) closed.** The design's `obsidian search query="..." format=json` syntax is verified live against `obsidian.md/help/cli` (active page, not a 404 anymore). The smoke chain hits real Obsidian when the CLI is enabled in the user's Settings; otherwise degrades cleanly.
- **Filters + scoring.** `--author X` exact match against frontmatter `author:` field; `--tag Y` membership match against frontmatter `tags:` (inline or block list — anchor-to-NR==1 awk per P3 §1+§2). Score = file hit-count, with Obsidian's relevance rank as the primary sort dimension when Stage-2 ran. `--limit N` truncates after sort (default 20). Sort tie-breakers: path then line number for determinism.
- **Output shapes.** Default text mode: bulleted snippets (`- path:line (score N) [tags]\n    snippet`). `--format json`: `{hits: [{path, line, snippet, score, author, tags, obs_rank}]}` for agent consumption. Exit codes: 0 = at least one hit, 1 = no hits (same in both modes — shell consumers can pipeline).
- **`templates/vault-init/wiki/bases/`.** Three starter Obsidian Bases for human-side queries: `by-author.base` (group articles by author), `recent.base` (table sorted by `last_curated`), `draft-staleness.base` (drafts by age). Bases syntax verified against `obsidian.md/help/bases/syntax`. Neutral content per Risk #7 — no project-specific filters.
- **`README.md` final polish.** Quickstart now uses the marketplace (`/plugin marketplace add Abeansits/kunskap-marketplace`); three core flows (capture, curate, recall); Risks #5 / #7 / #8 surfaced inline; status reads v1.0.
- **`Abeansits/kunskap-marketplace` repo.** New public repo carrying `.claude-plugin/marketplace.json` (per the canonical schema at `code.claude.com/docs/en/plugin-marketplaces`) that lists the kunskap plugin with `source: github` pointing at `Abeansits/kunskap`. Plugin repo + marketplace repo are content-free and public; vault repos remain private (Risk #8).

Marketplace.json shape lint. Full prior-phase regression suite. Drift lints (P1 §7, P4 §7, P4 §9) extended to the new surface.

## v0.5.0 — 2026-05-05 — P5 role assignment + sandbox fix

- **`_meta/roles.toml` enforcement.** `bin/kunskap curate` and `bin/kunskap lint` refuse to run unless `kunskap whoami` matches `roles.<role>.primary`, except with `--force` (interactive confirmation; pass `--yes` or set `KUNSKAP_AUTO_CONFIRM=1` in scripts; recorded as `forced=true` in `_meta/last-run/<role>.json` for audit trail). Single-primary, no fallback, no advisory lock — design §Q4 explicitly rejected the lock variant after a TOCTOU finding in pass-2 review. Missing or `primary="TBD"` warns and proceeds (solo and freshly-init'd vaults must work without role config).
- **CWD-fix for headless agents (P4 §2 deferred).** `kunskap curate` and `kunskap lint` now `cd "$vault"` and pass `--add-dir "$vault"` before spawning `claude --plugin-dir`, so the agent's filesystem sandbox covers the vault from any working directory. Without this, running `kunskap curate --vault X` from any project dir other than `X` produced sandbox-blocked agent reads (manifesting as `[DRIFT]` self-check errors on the linter side and partial curator runs).
- **`_meta/last-run/{curator,linter}.json` recording (sharded per-role).** Curator agent writes `_meta/last-run/curator.json` on every successful run (`ran_at`, `by`, `inbox_processed`, `articles_written`, `drafts_routed`, `head_before`, `head_after`, `forced`); linter agent writes `_meta/last-run/linter.json` (`ran_at`, `by`, `findings_count`, `forced`). Sharded per-role so curator and linter never write the same file — preserves design §Q4's "no shared file both are racing on" invariant under multi-actor and hand-off scenarios (Codex Pass-2 found that a single shared `_meta/last-run.json` with jq-merge would conflict on rebase when two machines wrote different keys to the same file). The linter's write is the SOLE explicit exception to the read-only invariant (linter MUST 8 + MUST 9); the linter never touches `_meta/last-run/curator.json`. Atomicity: the run-record commit only fires on a clean run; partial / crashed runs leave no record, so the linter's `[CURATOR-IDLE]` clause naturally fires on the next vault audit.
- **CLI authoritative invariant whitelist (P5).** `bin/kunskap lint` enumerates every path touched between pre- and post-snapshots (commits since `head_before` AND new working-tree porcelain entries) and refuses any path that is not `_meta/last-run/linter.json`. Exit code 2 with a stderr listing of disallowed paths. Closes the gap between the linter's whitelisted single-write and the read-only contract (P4 §3 head-oid + porcelain pair generalized).
- **Preflight ordering (P1 §5 self-state-before-external).** `curate` and `lint` self-state checks fire in order: vault structure → agent-file → mid-rebase guard (P4 §4 reapplied) → identity (`whoami` exits 0) → role check → claude-on-PATH. Identity-not-set produces a clear "set identity first" message before any external dependency check.
- **TOML reader: documented constrained subset.** `bin/kunskap`'s awk parser stays — single-level table headers, double-quoted strings, no inline tables / arrays / multi-line strings / nested dotted-keys. The subset is documented in `docs/ARCHITECTURE.md` and locked by `tests/contract/toml-fuzz.bats`: subset-conforming inputs round-trip; out-of-subset inputs fail-soft (no crash, undefined value).
- **Two-machine identity simulation in tests.** `tests/contract/two-machine.bats` swaps `XDG_CONFIG_HOME` between two distinct `identity.toml` files against the same vault; asserts machine-A (matches `roles.curator.primary`) succeeds, machine-B (mismatch) refuses with `--force` suggestion, machine-B + `--force --yes` proceeds with override stderr.
- **CI lints (P4 ✨ deferreds).** Static-prompt fingerprint substring-collision detector scoped per agent (curator vs linter) — locks the discipline that each `*_prompt_contains` fingerprint is unique to its clause (P4 §7). CHANGELOG/README numeric-fact drift detector — fails on `\b<int>\s+(MUST|tests?|cases|bats)\b` (P4 §9 generalization of the P1 §7 hardcoded-test-count lint).
- **`README.md` documents the role hand-off procedure** + the multi-machine constraint at the top of "Status".
- `bin/kunskap version` bumps to `0.5.0`.

## v0.4.0 — 2026-05-05 — P4 linter agent

- `agents/linter.md` — read-only health-check agent (Karpathy "Linting"). Frontmatter: `model: opus`, `tools: Read, Bash, Glob, Grep`, `disallowedTools: WebFetch, WebSearch, Write, Edit`. The Write/Edit denial is the read-only invariant in code: the curator owns the wiki, the linter only audits.
- `commands/lint.md` + `bin/kunskap lint [--vault <abs-path>] [--format text|json]` — vault resolves from `--vault`, then the project marker (`.claude/kunskap.json`). Spawns the agent headlessly via `claude --plugin-dir` (P1 §2 lesson — directive prompt naming the agent, not slash invocation).
- Eight MUST clauses for the linter, each fingerprint-tested in `linter-static-prompt.bats`: `[DRIFT]` across articles (MUST 1), `[STUB-CLUSTER]` for 3+-ref orphans (MUST 2 — 2-ref is curator territory), `[DRAFT-STALE]` (≥7d created) + `[DRAFT-DEFERRED-STALE]` (≥14d deferred) (MUST 3), `[OFFLINE-ARRIVAL]` (MUST 4 — Risk #4, author not seen in `_meta/last-run.json#curator.by` for ≥48h), `[CURATOR-IDLE]` (MUST 5 — `ran_at` ≥48h ago or file missing), `[IDENTITY-MISMATCH]` (MUST 6 — committers in `git log --since=30.days.ago` not declared as `roles.<role>.primary`), the `[TYPE] path | message` output contract (MUST 7), and the read-only invariant (MUST 8).
- Read-only invariant enforced **at the CLI boundary**: bin/kunskap snapshots `git status --porcelain --untracked-files=all` AND `git rev-parse HEAD` BEFORE the agent spawn (so a pre-existing dirty vault isn't blamed) and compares post-run. Non-equal porcelain OR a HEAD oid change → distinct exit code 2 with a stderr diff. The HEAD-oid check closes the write+commit bypass; the `--untracked-files=all` flag ensures untracked-dir collapse can't mask a write deep in an existing untracked directory. Worktree-aware via `git rev-parse --is-inside-work-tree`.
- Output format: `[TYPE] path | message` lines grouped by severity in text mode; `--format json` emits a single `{findings: [...]}` object with `{type, severity, path, message, suggested_action}` records sorted by `(severity, type, path, message)` lexicographically (Pass-2 — cron-diff stability) and always exits 0 (the JSON IS the output). Text mode exits 0 when no findings, 1 when findings present (so cron / CI can use the exit code as a vault-health signal).
- Mid-rebase / merge / cherry-pick guard: `kunskap lint` refuses to run when the vault is in `.git/rebase-merge`, `.git/rebase-apply`, has `MERGE_HEAD`, or has `CHERRY_PICK_HEAD` — porcelain shifts during git rewrites would false-positive the read-only invariant check (P2 §3 mid-rebase-wedge lesson). The guard fires before the `claude` PATH check so the error is actionable on hosts without Claude Code installed (P1 §5 self-state-before-external ordering).
- MUST 4 14-day upper bound: `[OFFLINE-ARRIVAL]` only fires for inbox / archived notes whose `created:` is within the last 14 days. Without this bound, a brand-new shared vault that imports historical archives would emit one finding per pre-existing note from any author other than the first curator (Pass-2 finding).
- MUST 8 trust boundary clarified: the CLI's pre/post snapshot of `git status --porcelain --untracked-files=all` + `git rev-parse HEAD` is the authoritative invariant check; the agent's own `git status` self-check is best-effort defense in depth. If the two disagree, the CLI is right (Pass-2 alignment).
- `linter-static-prompt.bats`, `lint-cli.bats`, `linter-behavioral.bats` (gated `KUNSKAP_LIVE_TESTS=1`) — every linter MUST clause maps to a fingerprint test (P1 §1 safety net), every CLI surface (arg parsing, marker fallback, agent-file preflight, symlink shim, exit-code semantics) is exercised, every finding type has a behavioral assertion against a seeded scenario vault.
- Linter system prompt encodes the canonical anchor-to-NR==1 awk recipe for frontmatter parsing (P3 §1+§2 lessons — never use sed range patterns; many `wiki/**/*.md` files reads benefit) and the v0 §6 stub-discovery grep recipe verbatim.
- CI `.github/workflows/p4.yml`: shellcheck, manifest-version drift check, agent + command frontmatter shape, dynamic test-count printout, full bats regression suite, end-to-end `init → lint preflight` smoke (vault remains unmodified on failed preflight — read-only contract holds even when `claude` isn't on PATH).
- `bin/kunskap version` bumps to `0.4.0`.
